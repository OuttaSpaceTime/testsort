`.claude/docs/plans/plan-20260413-001.md`

## Planning Mode
Mode A — Scout-backed. Inherits from `scouts/001-testing-strategy-20260413.md`.

## TL;DR
Add 10 spec files and 1 support module. Unit tests for all pure-logic classes and prioritization strategies. One integration test for the `prioritized` command that serializes fixture data to a temp dir, runs the full pipeline, and asserts the built command string. No production code changes.

## Source Requirements
- Basic happy-path integration tests for CLI commands
- Unit tests for all core logic
- Test-first workflow (per CLAUDE.md)
- Real temp git repos for git-dependent classes (not stubs)
- Stub `system` for integration tests
- OpenStruct/double for CoverageMeasurement in strategy specs
- Mirror `lib/` directory structure

## Objective
Establish a test suite that covers all core logic with unit tests and validates the `prioritized` command pipeline end-to-end (minus the final `system` call).

## Before / After and Execution Flow

**Before:** `bundle exec rspec` runs 1 spec (version check). No logic is tested.

**After:** `bundle exec rspec` runs ~40-50 examples covering all core logic and the main CLI pipeline.

**Execution flow tested by integration spec:**
1. Serialized coverage data exists in temp dir (fixture setup)
2. Git repo has modified files (`:git` context)
3. `Testsort::CLI.start(["prioritized", "-s", "absolute"])` invoked
4. `Paths.last_run_stored?` → true (fixture files exist)
5. `CoverageMeasurement.new(from_disk: true)` → deserializes fixture data
6. `Changeset.new` → detects modified files from temp repo
7. `Absolute.new(changeset, measurement).prioritized_spec_order` → returns ordered list
8. Command string built → `"bundle exec rspec --order default spec/b_spec.rb spec/a_spec.rb"`
9. `system` stubbed → assert command string correctness

## Implementation Steps

### Step 1: Spec infrastructure
1. Modify `spec/spec_helper.rb`: add `Dir[File.join(__dir__, 'support', '**', '*.rb')].each { |f| require f }` and a guard that fails if any spec creates files under the real project's `testsort/` storage dir.
2. Create `spec/support/git_helpers.rb`: shared context tagged `:git` that creates a temp dir, inits a Rugged repo, stubs `Paths.root`, and cleans up in `after`.

### Step 2: Pure data object specs
3. `spec/testsort/configuration_spec.rb` — default values, setter/getter round-trip, `coverage_mode` hash structure.
4. `spec/testsort/prioritization/spec_spec.rb` — initializes with path, `times_covered` defaults to 0, is assignable.

### Step 3: Collection/mapping specs
5. `spec/testsort/coverage_measurement/file_to_index_mapping_spec.rb`:
   - `insert` creates bidirectional mapping
   - Lookup by string key returns index, by integer returns path
   - Duplicate `insert` is a no-op (`has_new_entries` = false)
   - `exclude?`/`include?` correctness
   - `file_list` and `count`
   - `fetch_specs` with known indices

6. `spec/testsort/prioritization/spec_list_spec.rb`:
   - `sorted_by_times_covered` returns ALL specs, highest first
   - `select_times_covered_sorted` returns only non-zero, highest first
   - Empty list edge case

### Step 4: Coverage matrix specs
7. `spec/testsort/coverage_measurement/coverage_matrix_spec.rb`:
   - Initialize empty → shape `[0, 0]`
   - Initialize with array → wraps it
   - `new_row` / `new_column` expand dimensions correctly
   - `[]` and `[]=` read/write cells
   - `times_covered_by_spec(file_indices)` sums correctly
   - `times_covered_by_spec` with bad indices → returns nil (ShapeError rescue)
   - `slice_by_files` returns correct submatrix
   - `slice_by_files` with empty indices → returns full matrix
   - `to_oneshot_lines` clamps all non-zero to 1

### Step 5: Changeset specs
8. `spec/testsort/changeset_spec.rb` (uses `:git` context):
   - Modified file: init repo, add+commit file, modify it → `affected` includes it
   - New file: init repo, create untracked file → `affected` includes it
   - Deleted file: init repo, add+commit file, delete it → `affected` includes it
   - Clean repo: init repo, add+commit → `affected` is empty
   - Files in `testsort/` storage dir are excluded

### Step 6: Strategy specs (shared fixture)
All three strategy specs use the same test fixture:
- A `CoverageMeasurement` double with a 4-spec × 3-file coverage matrix
- A `Changeset` double where `affected` returns `["app/models/user.rb", "app/models/post.rb"]`
- `code_file_to_index` maps those to indices 0 and 1

9. `spec/testsort/prioritization/strategies/absolute_spec.rb`:
   - Happy path: returns all 4 spec paths sorted by total coverage of affected files (descending)
   - Empty changeset: `affected` returns `[]` → `affected_file_indices` is empty → returns specs sorted by zero (all equal)
   - `select_covered_spec_list`: returns only specs with non-zero coverage
   - Single affected file: only one column contributes to ranking

10. `spec/testsort/prioritization/strategies/additional_pseudo_spec.rb`:
    - Happy path: returns specs ordered by bin-sorted coverage
    - Empty changeset: returns full `file_list` unprioritized
    - `in_groups: true`: returns array of arrays

11. `spec/testsort/prioritization/strategies/additional_spec.rb`:
    - Happy path: returns specs with greedy marginal coverage ordering
    - Empty changeset: returns full `file_list` unprioritized

### Step 7: Integration spec
12. `spec/testsort/commands/prioritized_spec.rb`:
    - Setup: create temp dir, stub `Paths.root`, build a `CoverageMeasurement` with known data, call `serialize` to write fixture files, create a temp git repo with a modified file
    - Happy path: invoke CLI with `-s absolute`, assert `system` called with correct command string containing specs in expected order
    - No coverage data: no fixture files → command is plain `bundle exec rspec`
    - No prioritized specs: changeset files not in coverage matrix → prints "no prioritized specs"
    - Random strategy: `-s random` → files passed directly, no prioritization

## Testing Strategy

| Scenario | Type | What's real | What's mocked/stubbed | Validates |
|----------|------|-------------|----------------------|-----------|
| FileToIndexMapping CRUD | Unit | FileToIndexMapping | Nothing | Bidirectional mapping correctness |
| CoverageMatrix operations | Unit | CoverageMatrix + Numo::NArray | Nothing | Matrix math, slicing, edge cases |
| SpecList sorting | Unit | SpecList, Spec | Nothing | Sort order, filtering |
| Configuration defaults | Unit | Configuration | Nothing | Default coverage_mode hash |
| Changeset per-status | Unit | Changeset + Rugged | Nothing (real temp repo) | Correct status flag interpretation |
| Changeset excludes storage | Unit | Changeset + Rugged | Nothing (real temp repo) | `testsort/` dir filtered out |
| Absolute happy path | Unit | Absolute strategy | Changeset (double), CoverageMeasurement (double) | Correct descending order by coverage sum |
| Absolute empty changeset | Unit | Absolute strategy | Changeset (double), CoverageMeasurement (double) | Graceful handling, all zeros |
| AdditionalPseudo happy path | Unit | AdditionalPseudo | Changeset (double), CoverageMeasurement (double) | Bin-sorted ordering |
| AdditionalPseudo grouping | Unit | AdditionalPseudo | Changeset (double), CoverageMeasurement (double) | `in_groups` returns array of arrays |
| Additional happy path | Unit | Additional | Changeset (double), CoverageMeasurement (double) | Greedy marginal ordering |
| Prioritized CLI pipeline | Integration | CLI, CoverageMeasurement (serialize/deserialize), Changeset, Strategy | `system` call, `Paths.root` | Correct command string end-to-end |
| Prioritized no data | Integration | CLI | `system` call, `Paths.root` | Falls back to plain rspec |

**Verification command:** `bundle exec rspec`
